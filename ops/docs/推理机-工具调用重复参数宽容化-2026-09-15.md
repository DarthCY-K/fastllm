# 推理机 FastLLM · 工具调用「重复同值参数」宽容化（2026-09-15）

## 起因（生产事件）

- 2026-09-15 00:07–00:17，Pi（经 subapi 中转）跑「鹈鹕骑自行车」单文件 HTML 任务，结束时客户端显示：
  `Error: Invalid tool call: malformed_tool_block at index None (Tool 'write' repeats parameter 'path')`
- 生产日志（`~/fastllm-video-repro/results/server-prod.service.log`，行 91125/91128/91129）：
  - `qwen3coder_tool_parser.py[line:543] WARNING: Failed to parse streamed Qwen tool call: Tool 'write' repeats parameter 'path'`
  - `fastllm_completion.py[line:3705] WARNING: Invalid stream tool call final state: malformed_tool_block at index None (Tool 'write' repeats parameter 'path')`
- 原始输出取证（`FT_TOOLCALL_DEBUG_OUTPUT=1`，chars=26978）：模型先输出
  `<parameter=path>C:/Users/45271/pelican-bicycle.html</parameter>` + 完整 HTML（收在 `</html>` + `</parameter>`），
  **随后在 `</function>` 前把 `path` 参数原样又输出了一遍**。块完整闭合 → 非 max_tokens 截断
  （区别于 09-13 23:51 的 `stream ended inside a tool-call block` 截断型；两次都出在同一任务上）。
- 影响：整块被拒 → 客户端没拿到 tool_call、约 10 分钟生成作废（HTML 实际上已完整生成）。
- 命中率：全日志 3797 条 chat/completions 请求中此类终态错误 2 次。

## 根因

- 模型侧：长工具块尾部退化——完成 content 后回卷复读参数列表开头的 `path`（与历史「！」字面循环同族的解码退化，随机事件）。
- 服务端：`Qwen3CoderToolParser._build_tool_call` 对重复参数名**一律抛错**（`Tool 'write' repeats parameter 'path'`），
  流式终结器把 parser error 升级为 `malformed_tool_block` 诊断并写入流。

## 变更（宽容策略：同值忽略 / 异值拒绝）

- 文件：`tools/fastllm_pytools/openai_server/tool_parsers/qwen3coder_tool_parser.py`（`_build_tool_call`）。
- 规则：同名参数再次出现且**原始值完全一致** → 记 warning 并丢弃重复项，工具调用保留；
  值不一致 → 维持原样拒绝（意图不可判定，不引入歧义解析）。
- 非流式 / 流式 / `FunctionCallParser` 门面三条路径共用该函数，一处生效。
