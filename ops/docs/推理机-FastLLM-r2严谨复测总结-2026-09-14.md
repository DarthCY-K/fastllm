# 推理机 FastLLM r2 严谨复测总结（AB5/AB6，2026-09-14）

**背景**：上午的 ab3/ab4 对比被审计发现口径问题（"greedy"未显式 temp0 / 32K 非全冷 / 分块参数实为两个口径 / 单样本无方差）。本轮按 **单变量 + 重复 + 逐块对账** 重做，回答四个问题：① 32K 冷预填 +7% 是否真实稳定；② 是否为 #730 的"256 分块新默认"所致；③ 相同分块下 r2 代码是否有额外成本；④ 顺带测 decode / 多轮恢复 / 确定性输出。

## 一、设计与方法

- 四配置、同一脚本、窗口内交错（三明治）：**A_pre**=现产(旧进程) → **B**=r2 默认(256 分块/256 快照网格) → **C**=r2+`FASTLLM_PREFIX_CACHE_SNAPSHOT_INTERVAL_PAGES=16`(512 分块/2048 网格) → **A_post**=现产(重启后)。
- **冷提示逐请求唯一化**（"Cold pass N." tag，消除前缀复用）；31,441 token 冷预填 ×3~5 重复；temp0 计数任务；20K 多轮续写（恢复长度探针）。
- **逐块对账**：解析引擎 `[Prompt] Long Prefill (pos/total) Speed` 全部块，Σ(块token÷块速度) 与客户端 ttft 的差额在全部配置恒为 ~0.16s → 全部性能差异可定位到预填内部。
- 窗口：AB5 14:14–14:27、AB6 14:31–14:38；生产中断合计 ~12 分钟，其余时间正常。

## 二、32K 冷预填（核心结果）

| 配置 | ttft 逐次 (s) | 稳定值 | vs 现产 |
|---|---|---|---|
| 现产 r1（旧进程） | 31.28 / 31.13 / 30.92 | ~31.1 | — |
| 现产 r1（重启后） | 31.59 / 31.46 / 31.13 | ~31.4 | +0.3（重启小效应） |
| **r2 默认**（新栈1） | 34.05 / 33.46 / 31.41 | — | 前两次 +2.8/+2.1 |
| **r2 默认**（新栈2，5 次） | 34.03 / 33.35 / **31.23 / 31.25 / 31.22** | **31.23** | **稳态 ≈ 0%（±0.1%）** |
| r2+16页（新栈） | 32.25 / 32.26 / 32.23 | 32.25 | +~1.0（且丢恢复收益） |

**分解**：
- **瞬态**：服务每次冷启动后，前 1~2 个长预填 +2~2.8s（首个 ~8K token 区速度 810→1065 恢复），第 3 个起消失；两个独立实例均复现（34.03/34.05 几乎相同）。现产 r1 的重启效应仅 +0.3~0.5s。
- **稳态**：r2 默认 31.23s 与现产 31.1–31.4s 同级 → **无稳态预填回归**。
- **C 的 +1.0s 在 2048 边界块**（谷更深、且缺 r1 的恢复冲高）→ 把快照间隔调回 16 页**不是**无代价回退项；C 为诊断配置，不建议部署。

## 四、正确性与确定性

- 计数类输出（d200 ×3、c32 ×3、tail40、q2）**四配置 md5 全部一致**（`dacc241c7db8` / `b536474ba172` / `aa7bf3a53f2c`）。
- **q1 散文（temp0、约 400 token）出现确定性分歧**：r1 与 r2+16页均输出 428 token（`31644a117142`）；**r2 默认（256 分块）两个独立实例均输出 415 token（`b5b1b18a9a49`）**。属"同提示 temp0 跨配置非逐字节"，随 256 分块配置出现；性质（无损翻转 vs 需要关注的漂移）未定，如做质量对比需专门评测。
- d200 全命中重复（d200_e/s 系列）输出亦全同。
