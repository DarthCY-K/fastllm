## 0. 为什么会有 ①：一次 Pi 输出异常中断的溯源

- 现象：Pi 会话（`网页优化`，11:24 起）最后一条 assistant 在 thinking 通道吐出整段多语种乱码（`stopReason=stop`、`input=97186/output=1131`），表现为"输出异常中断"。
- 引擎侧铁证（全日志仅此 1 次，就在日志末尾）：
  `[Fastllm] multimodal request failed: Qwen3.5 vision_config is incomplete. (returning an empty response).`
  紧随其后是同一请求的解码行（`[Qwen3.5 MTP] not enabled: draft cache was not seeded during prefill`，29–32 tok/s）。
- 根因链：生产包 `nerkyor/Qwen3.8-27B-EfficientThink-FP8-lm` 是**纯文本**（`Qwen3_5ForCausalLM`、无 `vision_config`、无视觉权重），而 **Pi `models.json` 的 `input` 仍含 `image`、Hermes `supports_vision: true`**（那是 09-15 给 NVFP4 包开的）→ Pi 把两张截图当 image part 发出 → 引擎拒绝并返回空响应 → 同请求继续解码产出垃圾。

## 2. ② 执行：生产 key 轮换 + 日志明文根因修复

- **暴露面测量**：`scan_key_files.py` 全机扫描 → **70 个文件含该 key**：live 生产日志 47 次（每次重启的 argv dump）+ env 文件 + 约 68 个测试栈日志（含两个 181MB 文件）。泄漏点 = `site-packages/ftllm/server.py` 的 `logging.info(args)`。
- **根因修复**（先做，避免新 key 又被写进日志）：泄漏点 = `site-packages/ftllm/server.py`（日志里的 `server.py[line:306]`）的 `logging.info(args)`。`ops/deploy/apply_nslog_redact.py` 幂等改写为
  `logging.info(type(args)(**{**vars(args), "api_key": "[REDACTED]"}))` —— 只改"打印用的对象"，真实 `args` 不动（鉴权不受影响）；留备份 `.py.bak-pre-nslog-redact`。
- **轮换**：`ops/deploy/rotate_prod_key.sh`（`openssl rand -hex 32` → 写入 `qwen38-0.2x.env`，备份 `.bak-pre-rotate-20260916` 600 → 重启 → 验证）。结果 `ROTATE_KEY_DONE ok=1 new=200 old=401 noauth=401`；日志验证 `redacted_lines=1  new_key_leaks=0  old_key_leaks=0`；soak 看护已用新 key 重启（`ok=1`）。
- **中继同步（依赖链上的坑）**：链路为 Pi → `subapi.kjsygame.com`(156, nginx→sub2api) → **account#13 `DarthCY-Qwen-Local`** → `http://101.43.40.158:11452/v1`（盒子 8080 的 frps 端口）。轮换需同步该账号的 `credentials->>'api_key'`（`make_sub2api_key_sql.sh` 生成 600 的 SQL，`shred` 收尾）。
  **坑**：只改 DB 不够——sub2api 有凭据缓存，会先用旧 key 打上游 → 401 → **自动把账号置为不可调度**（`account_disabled_auth_error` / `not_schedulable=1`），表现为客户端 502/503。修法：`fix_account13.sql` 复位（`status='active', schedulable=true, 清 error_message/temp_*`）+ `systemctl restart sub2api` 清缓存 → 中继恢复正常。
- **历史擦洗**：`ops/deploy/scrub_old_key.py` 同长度就地替换（保持 inode、不改文件长度）→ **68 个文件、68 处**已抹除；复扫只剩当前 env（新 key）。**遗留**：live 生产日志中 47 处旧 key 未抹（就地改 live 追加日志会丢尾部数据），该 key 已失效，留待下次停服务窗口处理。
