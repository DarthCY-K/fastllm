# 推理机 FastLLM · 多模态前缀缓存复用修复（2026-09-16）

## 起因（生产症状）

- Pi（经 subapi）在含图片的会话中每回合 `cached_tokens=0`、页脚 `CH0.0%`，每回合全量重算（100K 上下文 TTFT ~100s）。
- 受控实验（直连 127.0.0.1:8080，同一请求发两次）：
  - 纯文本 36K：二发命中 36352；图片同文：二发仍 0（missed=36594）。
  - 对照：无图会话（跑分等）同窗口命中正常 → 与中转站无关、与引擎负载无关。

## 根因（源码级，插桩证实）

- 图片请求走 `Qwen35ForwardMultimodalInternal`（qwen3_5.cpp）分块预填（chunk 512），**分块循环里没有任何 `TryRecordPagedCache`**；文本长预填路径在每个分块边界有（实测每 512 token 一条 `Rec OK`）。
- mm 路径唯一记录机会在回合末，长度（如 27594）几乎不可能 `% pageLen(128) == 0` → `Rec bail: len cur=27594 pageLen=128 mm=6`。
- 结果：图片会话快照列表永远为空（`Rec OK mm=6` 计数 0），后续 Query 恒 0 → 零复用。
- DFlash 草稿播种本身正常（`MMSeed: canSeed=1 seedDFlash=1`），仅缓存快照漏记。

## 修复

- 文件：`src/models/qwen3_5.cpp`（mm 分块循环，每个页对齐边界记录）+ 记录/查询路径 `FT_PREFIX_DIAG=1` 门控取证打印（默认关闭；同 `FT_TOOLCALL_DEBUG_OUTPUT` 先例）。
- 开关：`FT_QWEN35_MM_CACHE_SEED`（默认开；=0 关闭本轮新记录，用于 A/B 与回滚演练）。

```cpp
if (context != nullptr && Qwen35MmcacheSeedEnabled()) {
    const int cachedTokens = context->cacheLen + st + curLen;
    if (cachedTokens % fastllm::GetPageLen() == 0) {
        context->TryRecordPagedCache(this);
    }
}
```

## 遗留观察

1. 已还原 mm 请求的"尾段增长"与文本同口径（+25 token/轮的小尾段不产生新对齐快照；长尾段会话的增长机制两端一致，后续如需可单独立项优化）。
2. 多模态历史在客户端侧被裁剪到"最近带图消息"（pi-image-prune 默认 1 条）；引擎侧快照按裁剪后前缀匹配，两端需保持一致。
3. `FT_PREFIX_DIAG=1` 取证打印保留（默认关）；如长期不用可在下次版本移除。
